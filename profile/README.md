<p>静态住宅 IP 被说成"长期项目的标配"，但真正决定它能不能撑住一个长期项目的，很少是"静态"这两个字本身。一条地址不变，不代表线路不变、不代表会话数够用、也不代表合同期内能换。这篇按五层往下拆：地址层买到的是什么、线路层的路径有没有变、会话层的并发怎么算、账号层一条线能放几个身份、商务层该锁哪几条条款。每一层给出可以直接问出口的问题，避免只对着报价单做决定。</p>

<h2>一、地址层：静态买到的是"不变"，不是"干净"</h2>
<p>静态只描述地址的生命周期，不描述它的历史。一条挂了三年没换过的地址，可能因为前任使用者留下过大量投诉记录而变得难用；反过来，一条刚分配的新地址可能很干净，但随时会被回收。这两件事必须分开评估。</p>

<h3>先确认"静态"覆盖到哪一层</h3>
<p>有的服务商说静态，指的是合同期内这条地址不换；有的说的是地址段不重新分配；还有的只是"续费时优先保留"。三种承诺的实际含义差很多，问的时候直接要一句话：这条地址在我停付之前，是否会出现在别处。</p>

<h3>再查它过去是谁在用</h3>
<p>用 whois 看分配时间，用公开的滥用记录库看近 90 天的投诉条数，用两三个 IP 情报库交叉看类型标签。三项都干净，才谈得上"干净且稳定"；只干净不稳定，迟早要换；只稳定不干净，换了也没用。</p>

<h2>二、线路层：地址固定了，路径仍可能每天在换</h2>
<img src="/tp.png" alt="静态住宅IP五层结构里地址层与线路层的对应关系">
<p>出口地址是终点，路径是过程。跨境访问的实际路径由运营商互联和上游调度决定，晚高峰时同一条地址的路径可能绕行另一个国家。地址没变、路径变了，体验照样会波动，而你在监控面板上看到的"在线"状态一切正常。</p>

<h3>用 mtr 看路径而不是只看 ping</h3>
<p>在三个时段各跑一次长探测，比如每次 100 个包，看路径里跳数的变化和每一跳的丢包。路径在晚高峰多出两三跳、或者某一跳丢包突然升到 5% 以上，说明拥塞发生在中间段，换地址解决不了，得换线路或换入口地区。</p>

<h3>把首包和长连接的差异分开看</h3>
<p>首包时间反映建连开销，长连接稳定性反映持续传输能力。登录页面看重前者，长时间对话看重后者。测的时候两条都记，只测一条容易得出错误结论：首包 120ms 但长连接每十分钟断一次，用起来比首包 200ms 但从不掉线更难受。</p>

<h2>三、会话层：并发上限藏在三个不同的口径里</h2>
<p>"支持多少并发"是报价单上最容易被误读的一栏。端口数、连接数、账号数三套口径混着说，签完合同才发现实际能用的只有宣称的三分之一。</p>

<h3>端口、连接、账号各是什么</h3>
<p>端口指同时可用的代理入口数量，一个端口可以承载多条连接；连接指同一时刻的 TCP 会话总数，浏览器一个页面就可能开出十几条；账号指允许绑定的业务身份数量。三者不是换算关系，是三个独立的限制，任何一项到顶都会表现为"突然连不上"。</p>

<h3>问清楚到顶之后会怎样</h3>
<p>超限时是排队、是拒绝、还是悄悄降级到共享池，这三种处理方式对应的排查难度完全不同。悄悄降级最麻烦：面板显示正常，实际出口已经换了，账号侧的表现却是登录地跳变。</p>

<h2>四、账号层：一条出口能承载几个身份，要先算清</h2>
<p>技术上一条出口挂十个账号也能跑，但环境隔离的意义在于出问题时能定位到具体哪个身份受影响。所有账号共用一条线，一旦这条线被限速或者被标记，全部一起受影响，排查时也没有对照组。</p>

<h3>按使用强度分组，而不是按人数</h3>
<p>轻量使用（偶尔登录看回复）和重度使用（每天长对话、频繁切换模型）对出口的压力不在一个量级。分组时先按强度分，再按地区分，最后才考虑按人分。一个运营人员管三个轻量账号，共用一条线通常没问题；三个重度账号共用一条线，晚高峰就会互相拖慢。</p>

<h3>给每组留一条备用出口</h3>
<p>备用出口不需要和主出口同规格，能保证基本登录即可。它的作用不是提升性能，而是在主出口维护或异常时，让业务不至于完全停摆。备用出口平时不用，也要定期登录一次，避免长期闲置后被回收或状态变化。</p>

<h2>五、商务层：长期项目真正锁住的是替换条款</h2>
<p>长期项目最怕的不是贵，是中途换不掉。合同里如果只写了月费和地址数量，没写替换规则，出问题时只能被动等待。</p>

<h3>四条必须写进合同的条款</h3>
<p>替换是否免费、每月可替换次数、提交后多久生效、替换后是否保证仍为住宅段。四条里"多久生效"最容易被忽略，工单排队三天和三小时，对业务的影响差一个量级。</p>

<h3>退出成本也要提前问</h3>
<p>年付折扣通常伴随锁定期，中途退出是否退剩余费用、是否收取违约金、数据与配置能否导出，这些在签约前问清楚，比事后协商省事得多。价格区间因地区与服务商差异较大，本文不做具体报价，实际以合同为准，仅供参考。</p>

<h2>常见问答</h2>
<h3>静态住宅 IP 一定比动态的更适合长期项目吗？</h3>
<p>答：多数情况下是，但前提是这条静态地址本身干净。长期项目的核心诉求是登录地稳定，静态地址能满足这一点；如果地址历史记录差，稳定性带来的好处会被频繁验证抵消。先看纯净度，再看是否静态。</p>
<h3>并发上限写 50，为什么开到第 20 条就报错？</h3>
<p>答：大概率是口径不一致。50 可能指端口数或短连接数，而你开的是长连接；也可能单端口还有隐含限制。让对方给出"单端口最大连接数"和"长连接是否单独计数"两个具体数字，再对一遍。</p>
<h3>线路绕行能自己优化吗？</h3>
<p>答：能做的有限。可选的是换入口地区、换上游运营商、或者在应用层做超时与重试。中间段的互联质量由运营商决定，客户端侧改不了，遇到持续性绕行只能换线路。</p>
<h3>一条出口放几个账号比较稳妥？</h3>
<p>答：没有统一数字，取决于使用强度。轻量账号三到五个共线通常可以接受，重度账号建议一到两个一条线。判断标准是出问题时能否快速定位，而不是单纯看数量。</p>
